## ⚡ The Eighteen Non-Negotiable Directives

1. **Physical Yield on `pointerdown`**: Interactive controls must compress (`scale(0.97)` to `0.98`) the millisecond touch or mouse down occurs. Never wait for `click` (pointer release).
2. **Zero Layout Shifts**: Never change `border-width`, `font-weight`, `letter-spacing`, `margin`, or `padding` across ANY dynamic state (`hover`, `focus`, `active`, `selected`, `pressed`). Always declare `border border-transparent` on base controls so outline or feedback states only alter color, never geometry. Animate exclusively compositor properties (`transform`, `opacity`). Signal selection via color contrast, background pills, or indicators; never by switching font weight or tracking, which alters glyph widths and causes horizontal layout twitching.
3. **Tabular Numerals**: All counters, prices, metrics, and data table columns must specify `font-variant-numeric: tabular-nums` (`tabular-nums`) to prevent horizontal jitter.
4. **Accessible Invariants**: Every icon-only button must have an explicit `aria-label`. Dialogs must trap focus and dismiss on `Escape`.
5. **Quiet Chrome & Anti-Pill Proliferation Invariant**:
   - **No Card Reflex**: Avoid the lazy reflex of putting everything in a bordered card. Rely first on spatial rhythm, typographic hierarchy, and baseline alignment.
   - **No Eyebrow Pills & Anti-Pill Proliferation**: Strictly ban decorative pill badges above page or section headings (e.g., `rounded-full bg-muted border text-xs` eyebrow pills), the unmistakable calling card of AI landing page boilerplate. Headings must command authority through weight, tracking, and optical scale, never by hiding behind a tiny pill kicker. Badges and pills are strictly reserved for functional operational telemetry (e.g. status indicators like `healthy`, `degraded`, or active counts). Never clutter editorial layouts, headers, metadata lines, or document titles with pill containers. Treat pills as high-friction operational punctuation, not cosmetic decoration.
6. **Concentric Corner Radii**: When nesting rounded elements, compute the inner radius using $R_{\text{inner}} = \max(0, R_{\text{outer}} - \text{Padding})$ to prevent lumpy, bulging corners.
7. **Anti-Crush Responsive Page Architecture, Macrostructural Intent & Navigation Anti-Truncation Invariant**:
   - **Macrostructural Intent & Anti-Convergence Invariant**: Layouts must reject the singular generative AI reflex: a generic hero with split illustration, three identical icon-topped card columns, numbered process steps, pricing cards, and an email input band above a boilerplate four-column footer. Every screen and full-page layout must declare an intentional macrostructural archetype (e.g. _Workbench, Manifesto, Bento Grid, Long Document, Split Studio, Index-First, Feature Stack, Rail_) governed strictly by the visitor's primary operational job (`subscribe`, `book`, `visit`, `attend`, `buy`, `try`, `sign up`, `hire`, `join`, `listen`). The interface action must sit where the category demands it (in the hero, sticky, or beside the core inventory). Strictly ban tacking an email signup form to the foot of pages where a mailing list is not native to the visitor's job.
   - **Anti-Crush Responsive Page Architecture**: Full-page layouts must guarantee minimum viable column widths ($W_{\text{col}} \ge 340\text{px}$). Never force 3-column grids into narrow containers (<1080px). Cards and surfaces must establish container queries (`@container`), flex child containers must specify `min-w-0` to allow truncation, and layout footprint sizers must enforce `max-w-full` with zero bleed on icon controls.
   - **Pill & Badge Anti-Crush Invariant**: All status badges, pills, and metric chips must declare `shrink-0 whitespace-nowrap` at the primitive level (`badgeVariants`). In card headers or split rows, the title block must declare `min-w-0 flex-1` while the badge cluster declares `shrink-0`, breaking into responsive vertical stacks (`md:flex-row`) to prevent long titles from squeezing adjacent pills into ugly multi-line text wraps.
   - **Navigation & Menu Anti-Truncation & Bounded Allocation Invariant**: Navigation menu link titles, dropdown menu labels, and command palette items must NEVER declare `truncate` or `overflow-hidden` on their primary text labels. Primary navigation titles must declare `whitespace-nowrap font-semibold` and title-badge clusters must declare `flex-wrap` so badges wrap gracefully without ever truncating or clipping the title. Submenu columns in mega menus and directories must enforce minimum column widths ($W_{\text{col}} \ge 220\text{px}$). Horizontal navigation bars must enforce bounded allocation (`maxVisibleItems`) with automatic `"More ▾"` overflow harvesting (`align="end"`), and container queries (`@container/nav`) to guarantee zero collision with trailing action clusters.
8. **Reversible Kinetic Affordances (No Gimmick Icon Animation)**: Icons must only be animated if they possess a _reversible mechanical affordance_ that preserves glyph identity and glides in and out back to its resting origin on pointer leave or release (e.g. sliding filter knobs, lifting trash lid, gliding paper plane, separating copy sheets). Strictly ban gimmick animations: never spin symmetrical operational icons in circles (e.g. rotating `+`), never vanish and redraw glyphs from empty space on hover/press (e.g. disappearing `✓`), and never shrivel geometry. Operational, mathematical, and confirmation icons (`+`, `-`, `✓`, `→`) must remain static by default.
9. **Component Dimension Invariants, Atomic Class Collision Defence & Absolute Basis Collapse Invariant**: Never merge multi-axis shorthand utilities (e.g., `size-full`, `size-auto`, `p-0`) after single-axis variant dimensions (`h-9`, `h-8`, `px-4`) inside `cn()` / `twMerge()`. `twMerge` treats multi-axis shorthands as conflicting with and purging preceding single-axis dimensional constraints, causing buttons and controls to crush to font line-height. When decoupling an interactive control into an outer layout wrapper and an inner visual/motion surface:
   - The outer wrapper must remain visually transparent and unpadded (`p-0 border-0 bg-transparent`) to prevent stationary ghost surfaces from peeking out during tap compression.
   - The inner motion surface must receive the variant classes (`buttonVariants`) and caller visual overrides (`className`).
   - Outer layout bounds (`w-full`, `flex-1`, margins) must be explicitly synchronized without overriding explicit variant heights.
   - **Preview Frame Symmetry Invariant**: Showcase frames, demo preview wrappers, and fixture harnesses must never specify arbitrary fixed or minimum heights (e.g., `min-h-[...]`) that conflict with the child component's canonical height token (`h-16`, `h-9`). Dimensions must be driven naturally by the component itself, or if a fixture container specifies a larger bounding height, it must explicitly center the component along the vertical cross-axis (`flex items-center` / `grid place-items-center`) so vertical optical margins remain 100% symmetric.
   - **Absolute Basis Collapse Invariant**: Floating popovers, dropdown flyouts, and mega menus rendered inside `position: absolute` containers with `width: auto` must NEVER declare `w-full` without an explicit width basis (`w-[660px] sm:w-[720px]` or `w-72 sm:w-80`). In CSS, declaring `w-full max-w-...` inside an auto-width absolute parent forces the browser to resolve against an unconstrained container, collapsing the entire grid to `min-content` and crushing columns into illegible single-word wraps. Always declare an explicit width basis paired with a viewport cap: `w-[...] max-w-[calc(100vw-2.5rem)]`.
10. **Component-Unified Kinetic Affinity & Optical Icon Proportion Invariant**:
    - **Lifecycle Binding (Icons as Intrinsic Organs)**: Icons nested inside interactive components (buttons, selects, tabs, cards, inputs) must never act as isolated interactive islands requiring the user to target their tiny 16px bounding box. They must be bound to the parent component's lifecycle so that hovering, pressing, focusing, or activating **any part of the parent component** triggers the icon's kinetic affordance synchronously. Components must bind icon controllers across `leftIcon`, `rightIcon`, and nested `children`, and enforce `pointer-events-none` on SVG paths with `group-hover` / `group-active` so the icon feels like a living, organic part of the component itself.
    - **Optical Scale & Boundary Invariant**: Interactive control variants (`buttonVariants`, `toggleVariants`, `toolbarButtonVariants`, `tabsTrigger`) must declare autonomous descendant sizing constraints for nested icons across all sizing tokens (`[&_svg]:size-3.5 [&_svg]:shrink-0 [&>div]:size-3.5 [&>div]:flex [&>div]:items-center [&>div]:justify-center`). Primitives must never assume that nested icons will self-regulate their internal dimensions.
    - **Explicit Parameter Rule on Motion Icons**: Components in `@/components/icons` render an outer `<div>` with an internal `<svg width={size} height={size}>` defaulting to $28\text{px}$. Callers and fixtures must ALWAYS pass an explicit `size={...}` parameter matching the container's optical target (e.g. `size={14}` for `sm`, `size={16}` for `default`), and must NEVER rely solely on a Tailwind `className="size-..."` on the outer `div` (which fails to constrain internal SVG attributes). Nested icons must maintain an optical container ratio between $40\%$ and $50\%$ of the parent's canonical height:
      - $28\text{px}$ container (`h-7`, `xs`) $\implies 12\text{px}$ icon (`size-3`, `size={12}`)
      - $32\text{px}$ container (`h-8`, `sm`) $\implies 14\text{px}$ icon (`size-3.5`, `size={14}`)
      - $36\text{px}$ container (`h-9`, `default`) $\implies 16\text{px}$ icon (`size-4`, `size={16}`)
      - $40\text{px}$ container (`h-10`, `lg`) $\implies 18\text{px}$ icon (`size-4.5`, `size={18}`)
11. **Perceptual Gradient Engineering & Dual-Engine Contrast Invariant (WCAG 2.2 AA + WCAG 3 APCA)**: Never apply saturated linear gradient text (`-webkit-background-clip: text` with neon ramps), the unmistakable calling card of AI boilerplate. Gradients are strictly reserved for functional optical physics: atmospheric ambient occlusion, 1px specular rim lighting, directional alpha masks, and soft chromatic lensing under Liquid Glass (`backdrop-filter: blur(20px)`). All CSS gradient ramps must interpolate in modern perceptual color spaces (`linear-gradient(in oklch, ...)`) to eliminate muddy sRGB gray midpoints. All themes, components, and surfaces must satisfy the **Dual-Engine Contrast Invariant**:
    - **Compliance Engine (WCAG 2.2 Level AA)**: Maintain $\ge 4.5:1$ for body text and $\ge 3:1$ for graphical UI boundaries and focus rings across every single coordinate stop.
    - **Perceptual Engine (WCAG 3 APCA)**: Must achieve $|L_c| \ge 60$ for interactive buttons/controls (font-weight 500+) and $|L_c| \ge 75$ for body reading text. On high-luminance hues (amber, yellow, gold), never force white text; always enforce negative-polarity deep obsidian text (`primary-foreground`) to eliminate optical irradiation and chromatic vibration.
12. **British English, Ban on AI Em Dashes, Editorial Swap Test & Negative Copy Lexicon**:
    - **British English Invariant**: All user-facing prose, document headings, interface descriptions, tooltips, and commit messages must strictly adhere to British English spelling (`prioritise`, `synchronised`, `colour`, `centre`, `behaviour`, `grey`, `dialogue`, `fulfil`, `judgement`, `programme`, `catalogue`, `analysing`).
    - **Ban on AI Em Dashes**: Never use em dashes (`—` or `&mdash;` or `--`) in prose or titles. Em dashes are the most common mechanical signature of LLM generation. Structure clauses using natural cadence: commas, colons, semicolons, or separate sentences.
    - **The Editorial Swap Test**: Every headline, value proposition, and section title must pass the swap test: if a competitor's name can be swapped into the headline without sounding incongruous, rewrite the copy using specific, concrete nouns, verified numbers, and distinct operations native only to this product.
    - **Screen Word Budget Invariant**: Fullness comes from visual scale, typographic hierarchy, and working product mass, never explanatory verbosity.
      - Hero headlines must not exceed 7 words (50 characters).
      - Section titles must not exceed 6 words.
      - Subheadings and leads must not exceed 12 words.
      - Any single $1440 \times 900$ viewport must not exceed approximately 80 visible words.
      - Complete marketing and showcase pages must not exceed 450 visible words in total.
    - **Negative Copy Lexicon & Banned AI Cadences**:
      - **Rebuttal Cadence**: Strictly ban pseudo-poetic rebuttal cadence (_"Not a tool. A revolution."_, _"Not just software. An experience."_).
      - **Filler Openers**: Strictly ban generic situational openers (_"Built for the modern team"_, _"In today's fast-paced digital landscape"_, _"Whether you're an X or a Y"_).
      - **Colon Titles**: Strictly ban formulaic colon titles (_"Focus: the app for..."_).
      - **Banned AI Buzzword Lexicon**: Strictly ban _seamless, robust, empower, supercharge, elevate, effortless, unlock, unleash, next-generation, world-class, best-in-class, industry-leading, mission-critical, future-proof, game-changer, journey, reinvent, reimagined_.
      - **Banned Template Punctuation**: Strictly ban decorative middle-dot joined metadata strings (`A · B · C`), arrows glued to button labels (`Learn more →`), and decorative status dots before plain text labels. Structure clauses with columns, hairlines, line breaks, or distinct semantic badges.
13. **Origin Anonymity & Self-Contained Integrity**: Never cite or reference external repositories, libraries, competitor design kits, or external online tools as the origin, inspiration, or derivation of components, tokens, or philosophies in pushed code, comments, or documentation. Present all architectures, primitives, tokens, and guidelines as autonomous, self-contained standards of this design system.
14. **Telemetry Indicator & Kinetic Cadence Invariant**:
    - **Resting Contrast Headroom**: Kinetic indicators, beacons, and radar nodes must maintain an optically light, quiet resting state (`bg-background`, softened perimeter border, zero static halo blobs) to preserve contrast headroom and high legibility for numerals, core dots, and glyphs.
    - **Kinetic Cadence & Resting Plateau**: Infinite pulse animations must enforce a periodic resting window ($\ge 60\%$ of cycle duration at `opacity: 0`) so the node spends the majority of its lifecycle in its calm, legible normal state between physical impulses.
    - **Strict Compositor Purity & Layer Encapsulation**: Keyframes must animate exclusively compositor properties (`transform`, `opacity`) paired with `transform-gpu` and `will-change-transform`. Strictly ban animating layout properties (`top`, `left`, `margin`) or CPU paint properties (`filter: drop-shadow`), which trigger continuous layout recalculations and invalidate the sampling buffers of sibling or ancestor `-webkit-backdrop-filter` glass surfaces (causing navbar and floating button flicker).
    - **Structural Punctuation over Data Cramming**: Indicator nodes must serve strictly as structural anchors (status, sequence, progress, actor identity). Never force multi-character data strings, currency pairs, raw emojis, or cartoon skeuomorphic metaphors into a 28px indicator circle; operational telemetry belongs in the accompanying content block.
15. **Brand Truth & Fact Integrity Invariant**:
    - **No Hallucinated Brand Assets**: Generative models must never guess or hallucinate brand colours, hex values, or typography from training memory ("memory hex = fail"). When styling for an established brand, extract values directly from verified stylesheets, token specifications, or explicit user directives.
    - **Factual Integrity & No Invented Telemetry**: Strictly ban fictional testimonials, invented case studies, synthetic metrics (e.g. "99.9% uptime" or "trusted by 10,000+ teams" without real data), and fake client logo walls. If metrics or testimonials are not supplied, omit the section or render an explicit empty slot container with required user asset guidance.
    - **Real Product Proof Over Mock Divs**: Never render styled-div "mock interfaces" with fake browser chrome (traffic lights, synthetic URL bars) where real product screenshots or working interactive component fixtures belong.
    - **Authentic Visual Assets & Licenced Photography**: Stand-in photography must be authentically sourced from verified open-licence archives with explicit author attribution in the footer colophon. Strictly ban fake stock human portrait hotlinks or generic stock illustrations.
16. **Micro-Finish & Layout Stability Invariant**:
    - **Form Helper & Error Slot Stability**: Form helper text, validation descriptions, and error slots must declare `min-h-[1lh]` to preserve line-height vertical baseline stability, preventing jarring vertical layout reflows when validation states toggle dynamically.
    - **Typographic Balance & Anti-Widow Invariant**: All display and section headings must enforce `text-wrap: balance` (`[text-wrap:balance]`). Body paragraphs and multi-line descriptions must enforce `text-wrap: pretty` (`[text-wrap:pretty]`) to eliminate trailing single-word stubs (widows).
    - **Container Capping at 1920px**: At $1920 \times 1080$, content containers must remain capped (typically $1360\text{px}$ to $1440\text{px}$); gutters expand while reading measure and grid columns remain strictly bounded.
    - **Browser Surface Theming Invariant**: Every theme must explicitly declare `::selection`, `caret-color`, and `scrollbar-color` to prevent unstyled default browser controls.
17. **Evidence Before Assertions & Verification Gate**:
    - **Empirical Execution over Premature Satisfaction**: Never declare work complete, fixed, clean, or passing without executing the fresh verification commands (`npm run invariants`, `npm run check`, `npm run test`, `npm run build`) and confirming exit code 0 within the current interaction. Strictly ban expressing premature satisfaction ("Done!", "Great!", "Fixed!", "Looks correct!") prior to fresh empirical execution.
    - **Engineering Rationalisation Defence**: Strictly reject internal rationalisations:
      - _"Should work now"_ $\implies$ Run the test and inspect terminal output.
      - _"Linter passed so compilation is guaranteed"_ $\implies$ Linter is not a typechecker or compiler; run `tsc -b && vite build`.
      - _"Visual change only, tests are unnecessary"_ $\implies$ Run `npm run invariants` to verify zero accidental layout shifts or prohibited token overrides.
      - _"Confidence replaces execution"_ $\implies$ Confidence is not evidence.
18. **Autonomous Rulings & Continuous Execution Protocol**:
    - **Rulings, Not Stalls**: During autonomous refactoring or implementation, do not park the session on minor design-engineering ambiguities, layout token nuances, or formatting preferences. The agent is authorised to deliver authoritative rulings: record each decision (`Ruling: <decision>, <justification>, <consequence if altered>`) and maintain forward velocity.
    - **Four Strict Cessation Conditions**: An autonomous execution cycle stops if and only if encountering:
      1. An irreversible or destructive data operation.
      2. A security or credential boundary.
      3. A shared remote side-effect outside the local branch (merging/pushing to production or unapproved remotes).
      4. A fundamentally contradictory specification where every forward path is guesswork.
